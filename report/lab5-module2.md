# Lab 5 模块二与 Challenge 2

分工负责人为崔迪（2412439）。本模块让内核线程装载第一个用户程序，经 `sret` 进入用户态，并在进程退出后由父进程回收资源。

## 首个用户进程

`proc_init` 从 idle 进程创建 init 内核线程。init 启动 `user_main` 并进入 `do_wait`。`user_main` 默认选择 `exit`，构建时也可以用 `make build-hello` 或 `make build-testbss` 选择课程用例。

`load_icode` 检查 ELF 文件头、程序头表、段的文件和虚拟地址范围，以及入口是否位于可执行段内。它根据 `PT_LOAD` 建立 VMA 和页表，按段权限映射用户页，拷贝文件中的字节并清零 BSS。栈区预留 `USTACKSIZE`，首次进入用户态前实际映射栈顶四页。`do_execve` 检查名称和 ELF 所在的地址范围及页面，先用源数据构造新映像。构造失败时释放临时地址空间，成功时切换页表并释放不再被引用的旧地址空间。这一顺序允许 ELF 源数据位于旧地址空间。

`kernel_execve` 通过 `forkrets` 进入公共 Trap 返回路径。Trapframe 的 `epc` 保存 ELF 入口，`sp` 指向用户栈顶，`sstatus.SPP` 清零使 `sret` 进入 U 态。进程退出后，`do_wait` 从僵尸子进程取得退出码，移除 PID 登记和进程链接，再释放内核栈与 PCB。父进程在关中断期间检查子进程并设置 `WT_CHILD`，以配合退出侧的唤醒。 [模块实现](../code/kern/process/proc.c)

## 规格与提示词

规格要求从现有 Lab 4 内核线程启动 ELF，保留进程接口和课程测试选择方式。ELF 必须按段装载，拒绝越界或重叠段，失败时回收已分配的页表和内存。`do_wait(0, ...)` 等待任意子进程，正 PID 仅等待指定的直接子进程。非法写回地址应立即报错，父进程可以用合法地址重试。

## 验证与修正

在 RISC-V GCC 10.2 和 QEMU 11.0.2 下，用临时系统调用、缺页和进程退出测试桩运行以下用例。正式分支的完整构建仍依赖待实现的系统调用。

| 用例 | 观察结果 |
| --- | --- |
| `hello` | 首个用户程序以 PID 2 输出 `hello pass.`。init 等待并回收后输出 `init check memory pass.`。 |
| `testbss` | 程序验证了 4 MiB BSS 的清零和读写，随后在预期的越界写处触发用户态缺页。init 通过内存回收检查。 |
| 指定 PID 等待 | 正确写回子进程退出码。非法 PID 和非法写回地址均返回错误，使用合法地址重试后才回收子进程。 |
| ELF 部分装载失败 | 构造了两个已映射页表区域，再让装载因第三个重叠段失败。拒绝映像后，可用物理页数量恢复到调用前。 |
| 从旧用户空间执行新映像 | 未映射的源指针和错误入口均被拒绝，旧地址空间仍可用。随后从同一用户栈位置提交合法 ELF，切入新入口并以预期的退出码结束。 |

第一次交叉编译发现课程的 `bool` 类型未定义 `true` 和 `false`，因此沿用项目约定的 `0` 和 `1`。ELF 部分装载失败的对照测试中，原 `exit_range` 在清理第一个 VMA 后提前释放了仍被其他 VMA 使用的中间页表，导致空闲页计数断言失败。修正后，只有全部子页表均已释放才回收该中间页表。 [页表回收实现](../code/kern/mm/pmm.c)

## Challenge 2 用户程序何时预加载

**构建时嵌入镜像，启动用户进程时建立用户映射。** Makefile 先使用 `tools/user.ld` 将 `user/` 下的程序链接为独立的用户 ELF，再把这些 ELF 作为二进制数据链接进内核。引导环境将内核镜像载入物理内存时，嵌入的 ELF 字节随镜像一起进入内存。用户程序此时还没有自己的页表映射。 [构建规则](../code/Makefile) · [用户链接脚本](../code/tools/user.ld)

运行时，`user_main` 通过链接器提供的起始地址和大小符号选中 ELF。内核为 `PT_LOAD` 建立用户映射，复制文件中的字节并补零。`readelf -l` 显示 `testbss` 的可写段文件大小为 0，内存大小为 `0x400000`，这 4 MiB 在装载时分配并清零。CPU 随后经 `sret` 从 ELF 入口开始执行。 [装载实现](../code/kern/process/proc.c)

以 Linux 上常见的 `execve` 为例，内核在运行时通过路径从文件系统取得 ELF，建立文件映射，程序页可按需调入，动态链接程序还可以由 ELF 指定的解释器装载共享库。Lab 5 把可执行文件随内核镜像提供，启动路径因此可以直接验证 ELF 装载、页表切换和特权级切换。
