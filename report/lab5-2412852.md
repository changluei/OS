## 模块一 · 用户态系统调用

- 用户调用桩用 RV64 的 `a0` 传调用号，以 `a1–a5` 传参数，未使用的参数槽置零。内联汇编声明 `a0` 同时是输入与输出，允许编译器按 C 接口把结果取为有符号 `int`。 [用户调用桩](../code/user/libs/syscall.c)
- `trap` 将保存的帧挂在 `current->tf`。遇到 U 态 `ecall` 时，`exception_handler` 先把保存的 `epc` 前移 4 字节，再调用 `syscall`。分发用完整的 64 位调用号检查表长和空槽，再把返回值写入帧里的 `a0`。无法处理的其他 U 态异常以 `-E_FAULT` 结束进程，父进程仍可回收。现有汇编根据 `sstatus.SPP` 恢复对应的栈和 `sscratch`。 [异常分发](../code/kern/trap/trap.c) · [Trap 汇编](../code/kern/trap/trapentry.S)
- 九个 `sys_*` 封装把各寄存器参数传给进程管理和控制台接口。`sys_fork` 交付当前帧和用户栈指针，新子进程的 `a0=0` 由 `copy_thread` 建立。`wait`、`exec` 的用户指针沿用底层地址检查，`wait`、`kill` 的 PID 转换先验证能否用 `int` 表示。成功执行 `exec` 后，Trap 恢复的是新程序的入口和栈。`pgdir` 查询当前用户 VMA 的有效用户叶页，输出虚拟地址和 R/W/X 权限。 [分发与封装](../code/kern/syscall/syscall.c) · [地址空间校验与装载](../code/kern/process/proc.c) · [页表诊断](../code/kern/mm/pmm.c)

## 模块四 · 退出、让出与终止

- `do_exit` 保护 idle 和 init。在单核关中断区内，先从当前用户页表切回启动页表并刷新 TLB。最后一个 mm 所有者负责释放用户页、页表和 mm。随后记录退出码并进入 `PROC_ZOMBIE`，唤醒在 `WT_CHILD` 等待的父进程，把自己的子进程过继给 init，然后调度出去。过继仅更新父子及兄弟链接。PID 登记、PCB 和内核栈由 `do_wait` 在读出退出码后回收。
- `do_yield` 置 `need_resched`，在用户态 Trap 返回路径调度。来自 U 态的 S 时钟中断同样登记调度请求，使没有发起系统调用的忙循环也能交回 CPU。S 态时钟中断继续维护时钟，内核保持原有的单核协作式调度。
- `do_kill` 在同一个临界区查询 PID、验证目标、置 `PF_EXITING`，并唤醒处于可中断睡眠的目标。目标会在系统调用、用户态 Trap 或等待路径中终止。Trap 在正常服务异步中断后处理退出，并在调度返回后再次读取退出标志，覆盖切换期间收到的请求。 [进程控制](../code/kern/process/proc.c) · [时钟与 Trap 尾部](../code/kern/trap/trap.c)

## 规格、提示词与修正

模块一的规格来自课程的 ABI 和 `tools/test_lab5.c`。我把有效调用、稀疏表空槽、宽度越界、指针校验、成功替换程序映像和返回现场分别写成可观察的结果。模块四依据 `do_wait` 的等待状态和调度器对 `PROC_RUNNABLE` 的约定，把页表释放时序、父进程睡眠与唤醒、孤儿接管和重复终止写入规格。两份提示词列明可修改位置、依赖和接口，子 agent 按规格选择实现。 [四段式提示词](lab5-2412852-prompt.md) · [课程自检源码](../code/tools/test_lab5.c)

| 发现 | 修正 |
| --- | --- |
| 原用户调用桩无条件读取五个可变参数。GCC 15.1.0 的反汇编还显示 `sd a0,28(sp)` 将 64 位结果写到 32 位局部变量的位置，随后才用 `lw` 读取。 | 改为固定参数和显式寄存器约束。修正版的 `sys_getpid` 在 `ecall` 之后直接执行 `sext.w a0,a0`。 |
| 原时钟处理只重装计时并累计节拍。用户进程在忙循环中一直占用 CPU 时，需要时钟触发一次调度。 | U 态时钟中断登记 `need_resched`，由 Trap 尾部进入调度。 |
| Trap 尾部原先只在调度前读取退出标志。若目标在 `yield` 触发的调度中切出，重新运行时会从 `schedule()` 后继续，跳过之前的检查。 | 调度返回后重新读取 `PF_EXITING`。 |
| 子 agent 自审发现 `forkret → forkrets` 的首次进入路径绕过常规 Trap 尾部。若进程已被标记退出，其随后发起的系统调用可能先被派发。 | 在 U 态同步异常派发前检查退出标志。异步中断先完成服务或应答，再由尾部处理退出。 |

## 双重 GDB · 跟踪 getpid 的 ecall 与 sret

使用带调试符号的 QEMU 7.0.0 和宿主 GDB 12.1。宿主 GDB 直接启动 QEMU，来宾 GDB 通过 QEMU 的 Unix 套接字连接 RV64 CPU。选择 `yield` 中第一个 `getpid()` 作为观测点。该调用有明确的调用号 18 和 PID 2 返回值，返回现场可连续观察。 [课程双重 GDB 任务](../../lab2026/_book/lab5/lab5_4_gdb_ecall.html)

### 操作与现场

在构建目录运行 `DEFS=-Wno-error=int-conversion make build-yield`。以宿主 GDB 启动 QEMU，保留单线程 TCG，分别在 `helper_raise_exception`、`riscv_cpu_do_interrupt`、`helper_sret` 和 `riscv_cpu_set_mode` 设断点，按目标 `env->pc`、异常号或 `env->sepc` 过滤。

```sh
gdb --args qemu-system-riscv64 -machine virt -accel tcg,thread=single \
  -nographic -bios default -kernel bin/ucore.img \
  -S -gdb unix:/tmp/lab5-guest.sock,server=on,wait=off
riscv64-unknown-elf-gdb bin/kernel
```

在宿主 GDB 执行 `run`。来宾 GDB 用 `add-symbol-file obj/__user_yield.out` 加载用户符号，并执行 `target remote /tmp/lab5-guest.sock`。用反汇编确定 `sys_getpid` 的 `ecall` 地址，再在该地址设置硬件断点。单步进入 `__alltraps`，再执行一条指令观察栈交换。在内核 `sret` 设置断点，并限定 `$sepc == 0x8000aa`，区分启动首次进入 U 态和本次调用返回。执行 `si` 观察返回位置。地址随构建变化，以下为本次构建的实际值。

| 观察点 | 双重 GDB 实测值 |
| --- | --- |
| U 态执行 `ecall` 前 | PC `0x8000a6`，`a0=18`，`sp=0x7fffffd0`，`sscratch=0xffffffffc04a8000`。 |
| QEMU 送入 S 态 | `priv=0 → 1`，`medeleg=0xf0b509` 的第 8 位置位。PC 跳到 `stvec=0xffffffffc0200e0c`，`scause=0x8`，`sepc=0x8000a6`，`SPP=0`。 |
| 来宾执行 `csrrw sp,sscratch,sp` 后 | `sp=0xffffffffc04a8000`，`sscratch=0x7fffffd0`。进入 Trap 的第一条汇编完成两栈指针交换。 |
| S 态执行 `sret` 前 | PC `0xffffffffc0200ed2`，`sepc=0x8000aa`，`a0=2`。已恢复用户 `sp`，内核栈顶重新写入 `sscratch`。 |
| 返回 U 态 | QEMU 切到 `priv=0`，`SIE=1`、`SPIE=1`。来宾停在 `0x8000aa` 处的 `sext.w a0,a0`，`a0=2`。 |

### QEMU 的指令翻译和执行

QEMU 的 `trans_ecall` 将来宾指令译成 TCG 操作并调用异常 helper。宿主断点的回溯为 `helper_raise_exception ← code_gen_buffer ← cpu_tb_exec`，说明生成的宿主代码实际进入了 helper。`riscv_cpu_do_interrupt` 按来宾特权级确定异常号，再依 `medeleg` 写入 S 态 Trap CSR 并跳转到 `stvec`。陷入时的 `sepc` 仍指当前指令，`epc + 4` 发生在 uCore 的异常处理函数。

`trans_sret` 生成调用 `helper_sret` 的操作，把返回值作为新 PC，并结束当前翻译块。helper 检查权限、按 `SPP` 恢复特权级、用 `SPIE` 恢复 `SIE`，并返回 `sepc`。使用 QEMU 的 `-d in_asm,op` 并按地址过滤，记录到如下 TCG 操作。

```text
Priv: 0
0x00000000008000a6: ecall
 mov_i64 pc,$0x8000a6
 call raise_exception,$0x8,$0,env,$0x8

Priv: 1
0xffffffffc0200ed2: sret
 call sret,$0x0,$1,pc,env
 exit_tb $0x0
```

Lab 2 双重 GDB 同样把宿主侧的软件实现与来宾指令对应起来。TCG 执行来宾取指和访存时使用查找结果，软件 TLB 未命中时，`riscv_cpu_tlb_fill` 调用 `get_physical_address` 走来宾页表。Lab 5 观察的是指令翻译后触发的异常、特权级转换与续执行。 [Lab 2 双重 GDB 任务](../../lab2026/_book/lab2/lab2_4_qemu_mmu_debug.html)

调试前，主 agent 尝试在宿主调试器中选择 x86-64，发现已有的 RISC-V 交叉 GDB 仅支持来宾架构，于是解包宿主 GDB 到临时目录。子 agent 提醒用户调用桩在 `-O2` 下可能内联，主 agent 随后用 ELF 反汇编确认 `sys_getpid` 的指令地址。课程示例的 `exit` 终止当前进程，选用 `yield` 的 `getpid` 可以观测同一次调用的完整往返。汇编在首次启动和日常 Trap 返回时共用一条 `sret`，因此来宾按 `sepc` 筛选，宿主按 CSR 和特权级设条件断点，再用 TCG 日志交叉核对。首次采样后，宿主 GDB 退出时触发 `libthread_db` 断言。复测时用 `set libthread-db-search-path /nonexistent` 跳过该库，并通过 QMP 请求 QEMU 退出、等到应答后再关闭连接，完整采样后两个调试器均正常退出。

## 与操作系统原理的对应

| 原理 | 本实验中的具体体现 |
| --- | --- |
| 特权级和受控进入 | RISC-V 用 `ecall`、`stvec` 和 Trapframe 建立 U/S 边界。内核在可信的栈执行，验证用户传入的编号和指针。 |
| 进程状态与资源所有权 | `PROC_ZOMBIE` 保留退出信息，页表和 mm 先脱离，PCB 和运行过的内核栈在父进程等待后释放。孤儿由 init 接管。 |
| 调度与等待唤醒 | `yield` 是自愿交出 CPU，用户时钟是强制触发调度的入口，`WT_CHILD` 把睡眠与子进程退出关联。单核用中断屏蔽保持临界区一致。 |
| 地址空间和 TLB | 进程切换更新 Sv39 根页表，最后一个 mm 所有者退出时回收映射。解除活动页表引用后，刷新 TLB 再释放页表，避免继续使用旧翻译。 |

本部分没有覆盖多核调度和跨核 TLB shootdown、内核态抢占、完整的信号与权限模型，以及通过文件系统进行的动态装载。这些机制分别扩展了单核临界区、异步终止、地址空间和程序装载的实验模型。
