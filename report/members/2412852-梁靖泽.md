## 功能说明与 spec

### 核心接口

```c
int slub_init(void);
void slub_shutdown(void);
void *slub_alloc(size_t size);
int slub_free(void *object);
size_t slub_nr_slabs(void);
size_t slub_nr_live_objects(void);
int slub_check(void);
```

`slub_init()` 初始化缓存，必须在 `pmm_init()` 完成后调用；`slub_alloc()` 返回至少容纳请求大小的对象；`slub_free()` 释放由 SLUB 返回的对象，`NULL` 作为空操作处理。返回值使用 `SLUB_OK`、`SLUB_ERR_INVALID`、`SLUB_ERR_DOUBLE_FREE` 和 `SLUB_ERR_UNINITIALIZED`。`slub_shutdown()` 回收仍存活的缓存页和大对象页，调用后需要重新初始化才能分配。

### 实现约定

- 小对象使用 8、16、32、64、128、256、512、1024、2048 字节九个缓存，实际请求向上选择最近的缓存大小。
- 每个缓存从 `alloc_pages(1)` 获得一个 slab 页；页首存放 slab 元数据，剩余空间按固定槽大小组织空闲对象链表。
- 每个缓存对象前有固定大小的对象头，记录 magic、所属 slab 和空闲链指针；释放时检查 magic，避免重复释放破坏链表。
- 大于 2048 字节的对象直接通过 `alloc_pages()` 申请足够的连续页，并在独立页头链表中记录页数，释放时通过 `free_pages()` 完整回收。
- 最后一个对象释放后立即归还整个 slab 页；测试同时覆盖活跃对象存在时的 `slub_shutdown()` 全量回收。
- 本实现面向课程的单核同步环境，未加入并发锁；分配失败返回 `NULL`，非法指针不保证可安全探测。

[SPECIFICATION]
`slub_init()`
- **Pre-Condition**：物理页管理器已初始化；调用者尚未开始依赖 SLUB 对象。
- **Post-Condition**：SLUB 进入可用状态；首次初始化时各缓存和大对象跟踪状态为空。重复初始化不得破坏仍存活对象。
- **Case 1**：首次初始化成功，返回 `SLUB_OK`。
- **Case 2**：已初始化时再次调用，保持当前分配状态并返回 `SLUB_OK`。

`slub_alloc(size)`
- **Pre-Condition**：SLUB 已初始化；`size` 表示所需对象字节数。
- **Post-Condition**：成功时返回至少可写入 `size` 字节且满足模块对齐要求、与其他存活对象不重叠的地址；新对象计入存活对象统计。
- **Case 1**：`size == 0` 时返回 `NULL`，不改变分配器状态。
- **Case 2**：小对象请求成功时，从适当的对象缓存取得对象；释放同一缓存中的全部对象后，对应 slab 页可归还页分配器。
- **Case 3**：超过小对象缓存上限的请求成功时，取得足够的连续页面，并保留释放该对象所需的元数据。
- **Case 4**：SLUB 未初始化、底层页面不足或请求尺寸计算溢出时返回 `NULL`；不得错误登记部分分配。

`slub_free(object)`
- **Pre-Condition**：非空参数必须是当前仍存活、由本 SLUB 实例返回的对象。
- **Post-Condition**：成功时对象不再计入存活对象；对应存储回到缓存空闲集合，或其底层连续页被归还。slab 变为空时允许立即归还该页。
- **Case 1**：`object == NULL` 时作为空操作返回 `SLUB_OK`。
- **Case 2**：释放有效小对象时，更新所属缓存状态；对已释放的小对象再次释放应返回 `SLUB_ERR_DOUBLE_FREE`，且不得破坏缓存链表。
- **Case 3**：释放有效大对象时，准确归还其分配的连续页面。
- **Case 4**：SLUB 未初始化时，对非空对象返回 `SLUB_ERR_UNINITIALIZED`。调用者传入非本分配器对象属于违反前置条件；不得声称可安全识别任意无效地址。

`slub_shutdown()`
- **Pre-Condition**：SLUB 已初始化，底层页分配器仍可用。
- **Post-Condition**：释放 SLUB 管理的缓存页和大对象页，清空统计并回到未初始化状态；调用后重新分配前必须再次初始化。
- **Case 1**：有存活小对象或大对象时，仍回收 SLUB 持有的全部页面。
- **Case 2**：已处于未初始化状态时重复调用，不产生副作用。

`slub_nr_slabs()`、`slub_nr_live_objects()`
- **Pre-Condition**：无额外前置条件。
- **Post-Condition**：分别返回当前由 SLUB 持有的 slab 数量和存活对象数量；释放、回收或关闭后统计与实际状态一致。

## 实现与问题回答

SLUB 位于页分配器之上：页分配器只处理连续物理页，SLUB 在页内进一步切分固定大小对象。小对象复用 slab 页，减少每个对象一次页分配的开销；超过缓存上限的对象直接申请连续页，避免复杂的跨 slab 拼接。对象释放时先回收到 slab 空闲链，slab 全空后再将页归还底层分配器，因此页分配器的空闲页计数能够恢复。

这不是完整 Linux SLUB 的所有功能：当前实现没有 NUMA、CPU partial slab、并发锁、着色和 per-CPU 缓存，且缓存大小是固定的。对于本实验单核、固定地址映射和教学规模的需求，这种简化保留了“页级分配 + 对象级切分”的两层分配思想。

## 知识点与总结

- 页分配器和对象分配器是不同抽象层：前者保证连续物理页，后者管理页内对象生命周期；SLUB 通过 `alloc_pages()` 和 `free_pages()` 连接两层。
- 固定大小 slab 槽位使空闲对象可以用侵入式链表管理，不需要额外的通用堆分配器；缓存对象头中的所属 slab 指针支持释放时回收正确缓存。
- 大对象不能强行塞入小对象缓存，因此使用独立连续页路径；页头元数据必须与用户数据隔离，避免写入对象时破坏释放信息。
- 空 slab 立即回收和 shutdown 全量回收让资源状态可观测，`nr_free_pages()` 前后相等是页泄漏检查的直接证据。
- 本轮通过先编译、再 QEMU 分阶段输出定位运行时错误；第一次实现暴露出元数据覆盖问题，随后通过独立头部和真实页级测试修正。
