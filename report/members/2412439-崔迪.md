## 功能说明与 spec

- 输入来自现有 DTB getter；非法范围或内核/描述符放不下时终止初始化。
- 输出为 `va_pa_offset`、物理页号上界 `npage`、描述符数组 `pages` 和当前分配器的初始空闲区。
- 区分虚拟地址、物理地址、物理页号和描述符指针。`pages[i]` 对应物理页号 `nbase + i`，不是物理地址为零的页面。
- 可管理末端向下对齐且不超过框架上限；描述符起点与最终空闲起点向上对齐；仅注册非空的完整页面区间。
- 初始化所有描述符为保留状态后，再交给分配器清除真正可用页的保留状态，避免内核和元数据被提前分配。
- 最终默认构建选择 Best-Fit；显式 First-Fit 配置让本人可以在其他模块完成前验证自己的实现。

## 实现与问题回答

### 地址与描述符关系

本框架固定 `nbase = DRAM_BASE / PGSIZE`，因此描述符数量为 `npage - nbase`。先将链接器的虚拟 `end` 向上对齐得到 `pages`，再用 `PADDR()` 把数组地址转换为物理地址，核实全部描述符能放入内存。数组末端对齐之后才是可分配区间。

DTB 报告的 RAM 可能超过当前框架的管理范围，例如实测 256 MiB 场景报告末端为 `0x90000000`，而 `page_init()` 根据框架上限将可管理末端限制为 `0x88000000`。不足一页的尾部不纳入分配器。

## 知识点与总结

- DTB 描述硬件可用 RAM，内核的管理上限、镜像和元数据占用决定实际可分配页面；可用物理内存与可分配内存需要分别计算。
- 物理页号上界、实际页面数量、描述符数组下标是不同概念，本框架通过 `nbase` 建立对应。
- 管理结构本身占用受管理内存；先保留再登记空闲区，使这一占用可以被分配器正确排除。
- Sv39 支持在上层页表项直接终止的大页映射，不能预设每次翻译都恰好读取三层页表。

## QEMU 源码调试结果

实际日志见 [MMU/TLB 调试记录](../logs/2412439-mmu.txt)，新增工具为 `code/tools/debug_mmu.py`。

- 宿主机 GDB 启动原生 aarch64 QEMU，按目标地址设置条件断点；QEMU 自身调试和内核调试在两个独立运行中进行，避免把 GDB 读取内存触发的页表查询当成 CPU 访存。
- 裸地址取指：`addr=0x80200000`，SATP=0，`mmu_idx=1`，输出物理地址仍为 `0x80200000`，随后软件 TLB 仍被填充。
- 数据读取：真实调用栈包含 `full_le_ldul_mmu`、`load_helper`、`tlb_fill`、`riscv_cpu_tlb_fill`、`get_physical_address`。读取目标 DTB 页时，旧读标签是另一个页，确认发生软件 TLB 未命中。
- 页表遍历：在读取 PTE 后的源码行暂停，确认 `levels=3`、`i=0`、`ptshift=18`，PTE 物理地址 `0x80205ff8`，内容 `0x200000cf`；单步确认合法叶子分支，返回 `PA=0x82200000`、`prot=7`。
- 缓存填充：`tlb_set_page_with_attrs()` 接收 VA `0xffffffffc2200000`、PA `0x82200000`、size=4096。填充后标签匹配目标页，使用 `addend` 定位的 host RAM 中确实是 DTB 魔数字节。
- 内核指令核对：RISC-V GDB 在 `dtb_init()` 中停于 `0xffffffffc020028a: lw a5,0(a4)`；`a4=0xffffffffc2200000`，单步后低 32 位为 `0xedfe0dd0`，与 host 侧数据相符。

源码位置：`target/riscv/cpu_helper.c:get_physical_address()/riscv_cpu_tlb_fill()`，`accel/tcg/cputlb.c:load_helper()/tlb_set_page_with_attrs()`，`include/exec/cpu_ldst.h:tlb_index()/tlb_entry()`。源码路径均相对于所用 QEMU 4.1.1 源码根目录。

本轮无需改变入口页表即可在课程 QEMU 4.1.1 启动。软件 TLB 缓存与真实 CPU 微架构不是一一对应关系：本例页表叶子覆盖 1 GiB，填充缓存时只登记访问所在的 4 KiB 页；裸地址模式的缓存还承担 host RAM 地址转换工作。

容器提示无法禁用 ASLR，但符号断点和上述实际数据检查均成功。日志中的 host 指针地址可随 ASLR 改变，不应硬编码进结论。
